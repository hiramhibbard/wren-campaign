# Site and DM Craft Trigger Extension

This is a mandatory companion to `state/rulings/dm-procedure-triggers.md` for ordinary play. It routes the DM craft/site procedures added by `DM_CRAFT_POLICY.md` and `SITE_RUNTIME_POLICY.md` without requiring the DM to remember them manually.

## Site activation trigger
Activate/load `SITE_RUNTIME_POLICY.md` when Wren enters, commits to explore, materially changes, or is likely to revisit a bounded site whose layout, inhabitants, time, hazards, resources, alarms, treasure, clues, or persistence can affect play.

Create only the minimum active-site state needed. Do not instantiate a full dungeon runtime for an incidental room with no durable branching state.

## Investigation / perception trigger
Whenever Wren searches, examines, listens, scouts, tracks, studies, maps, compares, questions, or otherwise investigates—or whenever a hidden feature/evidence should be perceptible—route through `state/rulings/perception-and-evidence.md`.

Default behavior: observation before interpretation; ask for method clarification only when it changes information/risk/time/noise/resources/procedure.

## Creature embodiment trigger
Whenever a creature becomes consequential beyond a single narrow stat lookup, route through `state/rulings/creature-ecology-and-behavior.md` as applicable.

Do not load full monster ecology merely because a creature name appears if the immediate task only needs a narrow verified mechanical field. Escalate when behavior, motive, lair, evidence, population, treasure, reaction, morale, or regional/site consequences matter.

## Intent-before-initiative trigger
At first meaningful contact with an intelligent or behaviorally motivated creature/NPC, determine established current intent/orders/motive before treating the scene as combat.

If disposition is already established, use it. If genuinely uncertain, route to the normal reaction procedure. If combat begins or danger escalates, keep morale active when governing circumstances call for it.

## Evidence-footprint trigger
When an established creature/population/faction/environmental process has been present long enough that its behavior should plausibly leave signs, generate/maintain only causal evidence. Do not add breadcrumbs merely to guide Wren.

## Site-time trigger
When actions inside an active site consume consequential exploration time, update the nearest relevant time threshold/check rather than treating the site as timeless. Route source mechanics through AD&D 2e authority.

## Noise/alarm trigger
When an action creates consequential noise or visible disturbance inside an active site, evaluate only inhabitants/processes that could plausibly detect/respond based on current layout, senses, barriers, distance, source procedure, and alert state.

## Site-persistence trigger
When Wren changes an active site and then leaves or enough time passes, schedule/process only relevant surviving inhabitants/processes. Do not reset source-keyed state.

## Treasure-provenance trigger
When treasure ownership/location/history can affect clues, factions, danger, value, later recovery, or world coherence, establish enough provenance to explain why it is there and what moving it changes. Skip this for routine inconsequential loot.

## Playability-filter trigger
Before adding or surfacing bookkeeping, ask whether its possible outputs can affect a meaningful decision, consequence, resource threshold, uncertainty, or atmosphere. If not, collapse it.

This never authorizes skipping correctness-critical rules, due-event processing, legitimate encounter checks, active effects, resource depletion, source-mandated consequences, or persistent campaign changes.

## Scenario-not-story invariant
No trigger may be invented solely to force a desired scene, plot beat, combat, revelation, solution, or ending. Prepared situations and causal state may create consequences; Hiram's choices and legitimate resolution determine the path.
