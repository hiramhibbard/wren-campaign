# Regional Runtime Trigger Extension — v1

This file is a mandatory companion to `state/rulings/dm-procedure-triggers.md` for regional activation, encounters, weather, lore/knowledge reliability, and off-screen world motion.

Exact sourced mechanics route through verified structured projections and uploaded source authority.

## Regional activation trigger

Trigger when Wren:
- enters/approaches a region;
- commits to meaningful travel through it;
- investigates or repeatedly references it;
- activates a thread/adventure/faction whose consequences require it;
- advances time enough that a nearby actor/process can affect the current known-play area.

If no sufficient regional runtime profile exists, apply the Region-entry procedure in `REGIONAL_RUNTIME_POLICY.md` before consequential play depends on missing geography/environment/encounter state.

## Activation-horizon trigger

Whenever a new or changed actor/process can plausibly affect Wren's current/known area within the active campaign horizon, evaluate whether it must be promoted from latent to active.

If active, it must receive an explicit next reevaluation trigger/cadence or event condition. Do not leave independently moving consequential state dependent on DM recollection.

## World-motion due-event trigger

When in-world time advances or a registered condition/event occurs:
1. identify only active world elements whose reevaluation trigger was crossed;
2. resolve each from established goals/process/resources/geography/source state;
3. if multiple outcomes remain genuinely plausible, define the bounded outcome space before a genuine secret roll;
4. propagate only actual downstream dependencies;
5. schedule the next reevaluation if the element remains active;
6. preserve significant durable hidden changes for checkpointing.

Do not scan every faction/population/region every turn.

## World-state dependency trigger

When an actor/population/environmental process changes location, reach, resources, activity, or state, invalidate affected derived regional artifacts only.

Potential dependents include:
- encounter ingredients/table weights;
- encounter chance/population assumptions;
- routes/navigation;
- local traffic/economy;
- rumors/beliefs;
- faction awareness;
- weather/visibility;
- clues/threads.

## Random encounter trigger

When meaningful wilderness travel/exploration crosses a check slot required by the governing encounter projection/profile:
1. identify the current terrain/zone and applicable active source;
2. use valid prepared encounter-check projection (currently core DMG Table 56 where applicable);
3. if no local encounter content/table is prepared, generate it **before** rolling the encounter result from established ecology/social traffic/active world actors/source/adventure material;
4. make the secret occurrence/result rolls;
5. resolve encounter size/distance/surprise/reaction/morale from governing source/projections as needed;
6. persist consequential encounter/world-state results.

A lack of prepared monster entries does not cancel a legitimate check; prepare appropriate encounter content instead.

Do not trigger wilderness checks in ordinary settlement/interior activity unless a source/location/world state specifically calls for them.

## Encounter-content refresh trigger

Trigger when a world-state change alters who/what can plausibly be present in a region: migration, faction movement, patrols, alarm, disaster, adventure activation, ecology shift, supernatural reach, route change, etc.

Refresh affected encounter content before its next use. Encounter tables are derived from current world state; they do not create unsupported populations retroactively.

## Weather trigger

Trigger weather generation/refresh when:
- a new consequential travel day begins;
- sea/boat movement or safety depends on wind/weather;
- current weather duration/next-change condition is crossed;
- visibility/navigation/exposure/encounter context depends on conditions;
- an active environmental/magical process changes weather.

For qualifying sea travel use `adnd2e.dmg.travel.ship-weather.v1` unless a more specific explicitly active source governs.

Do not roll unused daily weather during inconsequential indoor/local downtime. If a weather state has continuing consequences, preserve a next reevaluation/ending trigger.

## Lore-generation trigger

Generate/retrieve deeper lore when:
- Wren enters/interacts with a location/entity whose coherence requires it;
- Wren asks someone, researches, recalls, investigates, or examines evidence;
- a source/adventure establishes the answer;
- an off-screen actor needs the fact to choose an action;
- a consequential clue/consequence requires an underlying hidden answer.

Generate only the minimum depth needed. Before a clue depends on an unresolved hidden answer, fix and persist the minimum necessary Established DM Truth first.

## Claim/reliability trigger

When an NPC/report/rumor/belief's accuracy or intent matters and is not already established, automatically invoke `state/rulings/knowledge-reliability-and-rumors.md`.

Do not default speech to true, false, or deceptive. Separate information access, speaker belief, communicative intent, and objective truth relation.

## Social belief/attitude trigger

When a consequential NPC attitude, trust judgment, misinterpretation, memory, or belief about Wren must be established:
- apply existing personality/alignment/relationship/context;
- use reaction or other governing AD&D procedure when appropriate;
- use bounded hidden randomness only where real uncertainty remains;
- persist consequential results and causes.

## New world-element creation trigger

Whenever play/source generation establishes a faction, monster population, organization, environmental process, disease, migration, trade pressure, supernatural force, or similar element, ask automatically:

`Can this independently change consequential state later?`

If no, keep it latent/simple.

If yes:
- create/promote an active world-element record;
- give it goals/process/resources/reach as applicable;
- assign an explicit reevaluation trigger;
- connect its downstream dependencies;
- do not wait for Hiram to ask whether it should advance.

## Combat-opportunity fairness

No trigger exists for "combat has not happened recently." Do not spawn/strengthen hostile actors to satisfy pacing.

Likewise, do not suppress valid hostile encounters merely because Wren is fragile. Consequences follow source mechanics, world state, reactions, morale, distance, avoidance opportunities, and player choices without plot protection.
