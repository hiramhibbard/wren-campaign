# Monster Projection and Encounter Runtime Triggers

This is a mandatory companion to `state/rulings/dm-procedure-triggers.md` whenever a monster/creature becomes relevant beyond a trivial descriptive mention.

Source selection is governed by `MONSTER_SOURCE_RESOLUTION_POLICY.md`. Resolve active scope before deciding whether the Monstrous Manual, a Monstrous Compendium/Annual, setting source, adventure source, or other active treatment governs.

Non-authoritative ecology enrichment is governed by `MONSTER_ECOLOGY_INSPIRATION_POLICY.md`. Inspiration is consulted only after the governing AD&D 2e source/scope is resolved and only for unresolved ecology questions.

## Monster source-scope trigger
Whenever a monster becomes consequential and one or more of the following are true, resolve source scope before using generic stats:
- an active campaign setting is established;
- an active published adventure/module is governing the site/encounter;
- the region/site uses setting-specific creature material;
- a specialized Monstrous Compendium appendix/Annual/source may contain an applicable treatment;
- a projection's scope does not obviously match the current situation;
- two available entries differ materially.

Do not default blindly to the Monstrous Manual, and do not import a specialized variant merely because it exists.

## First consequential monster use
When a monster type first becomes consequential and no adequate verified projection exists:
1. determine active setting/adventure/region/case scope;
2. resolve the governing source under `MONSTER_SOURCE_RESOLUTION_POLICY.md`;
3. retrieve the exact scope-resolved active AD&D 2e monster entry;
4. adjudicate from source authority;
5. evaluate whether a projection is justified under `MONSTER_PROJECTION_POLICY.md`;
6. if yes, create/verify/register a scope-aware projection without delaying play unnecessarily.

## Bilateral precedence trigger
If a specialized source is active and explicitly governs the creature in the current scope, use it rather than silently flattening the creature to the generic Monstrous Manual treatment.

If no specialized source is active for the current scope, retain the applicable generic/core treatment rather than importing a setting/adventure/Annual variant solely because it is available.

## Projection-use trigger
If a valid verified monster projection exists **for the resolved active scope** and covers the needed field, use it rather than rereading the source.

Escalate to exact source text when a field is missing, stale, exception-sensitive, ambiguous, the source scope/precedence is unresolved, or the field is explicitly marked `source-text-required`.

## Projection-creation trigger
Create or queue a monster projection when recurrence, active regional/site population, repeated combat, common encounter-table use, or Voice latency makes reuse worthwhile and the source is safely normalizable.

Projection identity/provenance must preserve governing source family and active scope. Do not overwrite a generic projection with a setting-specific version or vice versa when both treatments may be needed.

Do not create a projection solely because a monster appeared once.

## Companion-source trigger
When a non-governing Monstrous Compendium/source contains fuller ecology, society, description, or historical context, it may be consulted only for compatible non-conflicting detail under `MONSTER_SOURCE_RESOLUTION_POLICY.md`.

Do not silently merge contradictory mechanics, setting assumptions, abilities, habitat, behavior, rarity, or other fields into the governing treatment.

## Ecology-inspiration trigger
When the governing AD&D 2e/setting/adventure material and established campaign state leave a consequential ecology question unresolved, the DM may consult registered inspiration material under `MONSTER_ECOLOGY_INSPIRATION_POLICY.md`.

The sequence is mandatory:
`governing 2e source first -> identify gap -> inspiration candidates -> reject 5e/setting-incompatible material -> resolve campaign-specific old-school ecology -> derive consequences`

Never use the inspiration source to change mechanics, balance encounters to Wren's level, import 5e action/condition/challenge assumptions, or establish hidden truth without campaign resolution.

## Encounter-instantiation trigger
When actual creatures are encountered or otherwise become individually consequential, instantiate only necessary encounter state such as number present, HP, equipment, conditions, current intent/orders, morale context, limited-use abilities, carried treasure, leadership, affiliation, alert/pursuit state.

Once these facts affect play, preserve them. Do not regenerate them from the generic monster projection.

Adventure-specific modifications to named/specific creatures belong in encounter/site/population state unless the source defines a reusable scoped variant worth projecting.

## Population-promotion trigger
A one-off encounter does not establish a local population automatically.

Promote to regional/site population state only when source/circumstances support durable presence, lair/range, migration, faction/ecology effects, patrol activity, or repeated encounter relevance.

## Context/Voice trigger
When combat or close interaction is imminent, preload:
- relevant compact **scope-resolved** monster projection fields;
- actual encounter-instance state;
- resolved campaign ecology that can affect behavior/evidence;
- local site/regional context;
- governing source family/scope/locator and exception flags.

Do not preload unrelated monster entries, every Compendium variant, full monster books, or raw ecology-inspiration prose.

If source scope or a consequential unresolved ecology detail becomes uncertain during Voice and retrieval is unavailable, preserve the pending lookup rather than defaulting to core, a remembered setting version, or remembered 5e/fan lore.

## Invalidation trigger
Campaign injuries, deaths, equipment, morale outcomes, population movement, and encounter consequences invalidate/update encounter/population state only—not the generic monster projection.

Rebuild a projection only for source/version/verification/active-override changes. A setting/adventure scope change may select a different existing scoped projection without invalidating the prior one.
